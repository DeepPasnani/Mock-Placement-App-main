# Product

## Register

product

## Platform

web

## Users

**Admins (T&P Coordinators)** — College faculty running placement drives. They create tests, manage students, and review results. Their context is administrative: they need clarity, control, and efficiency. They may not be technical but need to set up coding challenges and auto-graded assessments.

**Students** — Engineering undergraduates (1000+ concurrent) taking timed aptitude and coding tests under proctored conditions. Their context is high-pressure exam mode: they need a UI that stays out of the way, communicates status instantly, and never surprises.

## Product Purpose

CampusTrack is a self-hosted mock placement platform that replaces fragmented tools (HackerRank, Google Forms, spreadsheets) with a single controlled system. It lets T&P cells run realistic placement drives — aptitude tests, coding challenges, auto-grading — at scale, with real-time monitoring and instant results.

Success looks like: a student opens the test, sees a clean full-screen interface, focuses on the questions for the entire duration, and gets results immediately after submission — without ever thinking about the platform itself.

## Brand Personality

**Technical. Restrained. Authoritative.**

- *Technical* — built by engineers for engineers; precision in every interaction, not decoration.
- *Restrained* — the interface never shouts. A single pine-green accent, warm bone surfaces, deliberate whitespace. Every element earns its place.
- *Authoritative* — this is serious work, not a game. The platform disappears so the test can take place. Quiet confidence.

## Anti-references

Not AI slop. This means a hard ban on:

- Gradient text, glassmorphism, decorative blurs
- Tiny uppercase tracked eyebrows above every section ("OVERVIEW", "FEATURES", "PRICING")
- Numbered section markers as default scaffolding (01 / 02 / 03)
- Side-stripe borders on cards
- Identical card grids repeated endlessly
- The hero-metric template (big number + small label + gradient accent)
- Hand-drawn / sketchy SVG illustrations
- Any pattern that signals "this was generated by a language model" rather than "this was designed for a purpose"

The existing dark design already avoids most of these. The commitment is to stay vigilant.

## Design Principles

1. **Light-first, not light-by-default** — The warm bone-and-cream theme is intentional for brightly-lit exam halls. Pale surfaces reduce contrast fatigue over 2–3 hour sessions. Every surface choice serves this use case rather than being a stylistic preference.

2. **Institutional confidence** — The interface communicates authority through restraint: warm cream backgrounds, precise typography, selective pine-green accent only for interactive or stateful elements. Nothing decorative.

3. **Clarity under pressure** — Students in exam mode must understand their status (time remaining, questions answered, flagged items) at a glance. Every notification, timer state, and palette indicator follows one convention without exception.

4. **Performance is UX** — With 1000+ concurrent users, every unnecessary re-render, oversized bundle, or blocking request degrades the experience. The UI treats performance as a design constraint, not an afterthought.

5. **Respect the user's attention** — Every element earns its place. Empty states guide the user. Error messages are specific and actionable. Confirmations are quiet. The interface never demands attention for its own sake.

## Accessibility & Inclusion

- WCAG AA target (baseline)
- `prefers-reduced-motion` respected — all animations degrade gracefully
- Light theme with warm matte surfaces minimizes glare in brightly-lit environments
- Focus-visible ring styles applied consistently across interactive elements (green accent ring)
- Tabular-nums for all scores and timer digits to prevent layout shift
- `::selection` highlight uses accent-tinted background for consistency
- Input placeholder text at full annotation color (4.5:1 minimum) — never the default muted-gray
